# Class Reflection (15th sept, 2026)


## 1. The Interface-Driven Core (`StyleFeature`)
The central pillar of this design is the **Open-Closed Principle (OCP)**. By creating the `StyleFeature` interface, we defined a strict contract that dictates how features interact with both the UI and the target `Shape`:

* **`getView()`**: Returns the UI section encapsulated within the feature.
* **`applyTo(shape)`**: Pushes local control values onto the shape properties.
* **`resetToDefault()`**: Restores local defaults independently.
* **`setOnChange(callback)`**: Establishes an observer pattern connection to signal repaint requests.

Because each feature (`FillStyleControl`, `BorderStyleControl`, `OpacityControl`, `EffectsControl`) implements this interface independently, none of the individual feature components know about each other's existence. This eliminates tight coupling and allowed us to isolate logic into focused, manageable classes.

---

## 2. Coordination without Coupling (`StylingPanel`)
The `StylingPanel` class acts as an aggregator and coordinator without taking on the burden of feature-specific rendering logic:

* **Polymorphic Management**: `StylingPanel` maintains a `List<StyleFeature>`. It iterates over this collection to construct the composite UI and register repaint callbacks (`setOnChange(this::applyAll)`).
* **Unified Paint Pipeline**: Calling `applyAll()` loops through all active features and executes `applyTo(target)`. This guarantees that any user interaction triggers a comprehensive style update without needing complex state tracking across separate modules.
* **Extensibility**: Adding a new styling capability (e.g., `ShadowControl`) requires zero structural changes to `StylingPanel`. We simply implement `StyleFeature` in a new class and append an instance to the feature list.

---

## 3. Clear Separation of Entry Point (`StylingApp`)
`StylingApp` serves solely as the bootstrap entry point. Its responsibility is restricted to setting up the JavaFX `Stage`, building the base layout (`BorderPane`), and binding the target node to the `StylingPanel`. Because the styling pipeline operates on the generic JavaFX `Shape` superclass, the application logic remains entirely agnostic of specific geometry, allowing us to seamlessly swap a `Rectangle` for a `Circle` or `Polygon`.
