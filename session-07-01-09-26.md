## 1. Drawing Triangles Using Equations

One of the interesting topics discussed was how geometric shapes such as triangles can be represented using mathematical equations and then drawn using programming.

Instead of thinking of a triangle only as three lines connected together, we can describe each of its sides mathematically. For example, a triangle can be represented using three line equations:

* `y = m1x + c1`
* `y = m2x + c2`
* `y = m3x + c3`

Each equation represents one side of the triangle. The intersection points of these equations give the vertices of the triangle.

This helped me understand the connection between **coordinate geometry and computer graphics**. A computer does not inherently understand that something is a triangle. We have to provide coordinates, equations, or mathematical rules that describe how the shape should be constructed.

It was particularly interesting to see that even a simple shape on a screen can be generated from mathematical relationships.

## 2. Drawing a Circle on a Canvas Using Right Click

We also discussed how mouse events can be used to make a graphical application interactive.

For example, we can configure the program so that when the user **right-clicks on a canvas**, a circle is drawn at the position of the mouse.

The basic logic is:

1. Detect a right-click event.
2. Obtain the mouse coordinates `(x, y)`.
3. Treat these coordinates as the center of the circle.
4. Draw the circle around that point.
5. Store information about the circle so that it can be used later.

This introduced the idea of **event-driven programming**. Instead of the program simply executing from beginning to end, it waits for an event such as a mouse click and then performs a particular action.

For example, conceptually:

```text
Right Click
     ↓
Get mouse position
     ↓
Create circle
     ↓
Draw circle
     ↓
Store circle
```

This is useful for understanding how interactive applications such as drawing tools, games, and graphical editors work.

## 3. Connecting Circles With Arrows

Another interesting part of the discussion was connecting the circles that we draw with arrows.

If circles are drawn at different positions, we can keep track of their centers and use those coordinates to draw lines or arrows between them.

For example:

```text
Circle A  ----->  Circle B  ----->  Circle C
```

If the center of Circle A is `(x1, y1)` and Circle B is `(x2, y2)`, the program can use these coordinates to draw a line from one circle to the other.

This showed me that graphical objects can be treated as **data**. Instead of considering a circle simply as something displayed on the screen, we can store information such as:

* Center coordinates
* Radius
* Order in which it was created
* Connections to other circles

Once this information is stored, the program can perform additional operations on the objects.

## 4. Keeping Track of Circles Using a Stack

A particularly important concept was how to keep track of the circles that we have drawn.

Suppose we draw circles in this order:

```text
Circle 1
Circle 2
Circle 3
Circle 4
```

If the requirement is to erase the circles that were drawn earliest, we need to keep track of their creation order.

We discussed using a **stack** as a data structure for this purpose.

A stack follows the principle:

> **LIFO — Last In, First Out**

This means that the most recently added element is the first one removed.

For example:

```text
Push Circle 1
Push Circle 2
Push Circle 3
Push Circle 4
```

The stack looks conceptually like:

```text
| Circle 4 |  ← Top
| Circle 3 |
| Circle 2 |
| Circle 1 |
------------
```

If we perform a `pop()` operation, Circle 4 is removed first.

This is useful for applications such as **undo operations**, where the most recent action is usually undone first.

## 5. Stack vs Queue

We also discussed the difference between a stack and a queue.

### Stack

A stack follows:

**LIFO — Last In, First Out**

Example:

```text
Push A
Push B
Push C

Pop → C
```

The last element inserted is removed first.

Real-world examples include:

* Undo functionality
* Browser history
* Function call stack
* Backtracking algorithms

### Queue

A queue follows:

**FIFO — First In, First Out**

Example:

```text
Enqueue A
Enqueue B
Enqueue C

Dequeue → A
```

The first element inserted is removed first.

Real-world examples include:

* Printer queues
* Customer service queues
* Task scheduling
* Breadth-first search

The main difference can be summarized as:

| Stack                        | Queue                                  |
| ---------------------------- | -------------------------------------- |
| LIFO                         | FIFO                                   |
| Last element leaves first    | First element leaves first             |
| `push()` / `pop()`           | `enqueue()` / `dequeue()`              |
| Useful for undo/backtracking | Useful for scheduling/order processing |

Understanding this difference helped me see that choosing the correct data structure depends on **how we want to access and remove data**.

## 6. Checking Whether a Point Is Inside a Circle

Another important mathematical programming concept was determining whether a particular point lies inside a circle.

The equation of a circle is:

```text
(x - h)² + (y - k)² = r²
```

where:

* `(h, k)` is the center of the circle
* `r` is the radius
* `(x, y)` is the point being tested

To determine whether the point is inside the circle, we calculate its distance from the center.

Using the distance formula:

```text
distance² = (x - h)² + (y - k)²
```

Then:

```text
If distance² < r²
    Point is inside the circle

If distance² = r²
    Point is on the circle

If distance² > r²
    Point is outside the circle
```

Using squared distances is useful because we do not need to calculate the square root.

This concept has many practical applications in programming, including:

* Collision detection in games
* Mouse interaction with graphical objects
* Selecting shapes on a canvas
* Detecting whether objects overlap
* Computer graphics

This was a good example of how a mathematical formula can directly become a programming condition.

## 7. Right Click and Drag

We also discussed the difference between simply detecting a **right click** and detecting a **right-click-and-drag** action.

A click generally involves:

```text
Mouse Press
     ↓
Mouse Release
```

Whereas dragging involves continuously tracking the mouse while a button is held:

```text
Mouse Press
     ↓
Mouse Movement
     ↓
Mouse Movement
     ↓
Mouse Movement
     ↓
Mouse Release
```

For a drawing application, this distinction is important.

A right click could create a circle at one specific location, while right-click-and-drag could potentially be used to:

* Move an existing circle
* Draw a shape
* Define the radius of a circle
* Select an object
* Create a connection between objects

This made me understand that mouse interaction is not just about identifying where the cursor is. We also need to consider the **state of the mouse button and the sequence of events**.

## 9. Mathematically Recognizing a Tree

One of the more interesting discussions was how we can mathematically determine whether a graph represents a tree.

A tree is a type of graph with specific properties.

For a graph with:

* `V` vertices
* `E` edges

a connected graph is a tree if:

```text
E = V - 1
```

However, the number of edges alone is not always sufficient. The graph must also be **connected** and contain **no cycles**.

Therefore, important properties of a tree are:

1. The graph is connected.
2. There are no cycles.
3. There are exactly `V - 1` edges.
4. There is exactly one path between any two vertices.

For example, if we have:

```text
V = 5
E = 4
```

and the graph is connected and has no cycles, it is a tree because:

```text
E = V - 1
4 = 5 - 1
```

This gave me a more mathematical way of understanding trees rather than seeing them only as diagrams.
