### 1. Event Handling

We discussed **event handling** in Java GUI applications. An event is an action performed by the user, such as clicking a button, selecting a checkbox, pressing a key, or moving the mouse.

Event handling allows the program to **detect these actions and respond to them**.

For example, when a user clicks a button, an event is generated and the program can execute a specific piece of code in response.

The basic idea is:

```text
User Action → Event → Event Handler → Program Response
```

Event handling is important because it makes a GUI interactive rather than just displaying static information.

## 2. Choice Components – Check Box vs Radio Buttons

We discussed two common choice components: **checkboxes** and **radio buttons**.

### Check Box

A checkbox is used when the user can select **multiple options independently**.

For example:

```text
☑ Java
☑ Python
☐ C++
```

Here, the user can select Java and Python at the same time.

### Radio Button

Radio buttons are used when the user should select **only one option from a group**.

For example:

```text
○ Male
○ Female
○ Other
```

Selecting one option normally deselects the previously selected option.

### Difference

| Check Box                        | Radio Button                            |
| -------------------------------- | --------------------------------------- |
| Multiple options can be selected | Usually only one option can be selected |
| Each option is independent       | Options belong to a group               |
| Used for multiple selections     | Used for mutually exclusive choices     |

## 3. Dialogue Boxes

A **dialogue box** is a small window used to communicate with the user or obtain information from them.

They can be used for:

* Showing messages or warnings
* Asking for confirmation
* Taking small amounts of input
* Displaying errors
* Asking the user to make a decision

For example:

```text
Are you sure you want to delete this file?

        [ Yes ]    [ No ]
```

### Alternatives to Dialogue Boxes

If we do not want to use a dialogue box, we can display information directly inside the main application window.

Some alternatives include:

* Labels
* Text fields
* Buttons
* Panels
* Status messages
* Inline error messages
* Notifications
* Dedicated screens or sections

For example, instead of showing:

```text
[Dialogue Box]
Invalid username
```

we can display:

```text
Username: [__________]

Invalid username
```

directly below the input field.

This can provide a smoother user experience because the user does not have to close an additional window.

## 4. JavaFX UI Using Swing and JavaFX Components

We also discussed creating a **JavaFX user interface** and the difference between JavaFX and Swing components.

Swing is an older Java GUI framework, while JavaFX is a newer framework designed for creating modern Java desktop applications.

A JavaFX application generally contains:

```text
Stage
  ↓
Scene
  ↓
Layout / Parent
  ↓
Controls
```

For example:

```text
Stage
 └── Scene
      └── VBox
           ├── Label
           ├── TextField
           └── Button
```

JavaFX provides components such as:

* `Button`
* `Label`
* `TextField`
* `CheckBox`
* `RadioButton`
* `ListView`
* `TableView`

Swing provides similar components such as:

* `JButton`
* `JLabel`
* `JTextField`
* `JCheckBox`
* `JRadioButton`

The main idea I learned is that **Swing and JavaFX have different UI component libraries and programming models**, even though both are used to create desktop GUI applications.

## 5. Master-Detail Layout in JavaFX

We also discussed the **master-detail layout**.

A master-detail interface divides the application into two main sections:

```text
+-------------------+-------------------------+
|                   |                         |
|      MASTER       |        DETAIL           |
|                   |                         |
|  Item 1           |  Information about      |
|  Item 2           |  selected item         |
|  Item 3           |                         |
|                   |                         |
+-------------------+-------------------------+
```

The **master section** contains a list of items, while the **detail section** displays more information about the item selected from the master.

For example, in a student management application:

```text
Students             Student Details

Alice                 Name: Alice
Bob                   Age: 20
Charlie               Course: CSE
```

If the user selects Bob from the master list, the detail section updates to show Bob's information.

This layout is useful for applications such as:

* Contact managers
* Email applications
* File explorers
* Student management systems
* Product management systems

The important concept is that the **detail view depends on the selection made in the master view**, which also connects back to the concept of event handling.
